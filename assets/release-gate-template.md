# 릴리스 검토 — 작성 양식

릴리스 ID: / 소유자: / 독립 검토자: / 검토일: / 상태: BLOCKED

G0 목적: 소유자·대표 과제·데이터·효과·비목표가 확정되었는가?

G1 설계: 고정 사양·SDK·호스트·프로파일, 신뢰 경계, C01–C16 판단, 도구 계약이 검토되었는가?

G2 구현: 실행 경계에 인가·승인·한도·출력·재시도 등 해당 통제가 구현되고 단위·정책 시험 증거가 있는가?

G3 통합: 실제 호스트·모델·프록시·하위 API, 장애·적대적 조합, 대표 과제와 Conformance 범위를 확인했는가?

G4 운영: 감사, 비밀 회수, 도구 차단, 복구·롤백, 보존·삭제, 변경 책임을 검증했는가?

## 시험 상태 집계

적용 / 통과 / 실패 / 미실행 / 해당 없음 / skip / expected failure / not_scored와 각각의 근거:

## 예외

예외 ID / 적용 통제 / 사유·영향 / 보완책 / 승인자 / 만료 / 재검토 계기:

사양 MUST 위반을 내부 예외로 ‘사양 준수’ 처리하지 않는다. 미통과 시험은 예외가 있다고 자동 통과가 되지 않는다.

## 판정

승인 / 차단 / 추가 검토 중 하나, 근거와 잔여 위험, 지원 범위·금지 범위:

기록 구조 검사 결과는 참고 자료이며 실제 서버 시험·증거 진위·보안 인증을 대신하지 않는다.
