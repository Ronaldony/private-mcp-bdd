# 검증 원칙과 인수 시험

T01–T36은 **시험 설계**이며 실제 MCP 서버의 시험 성적서가 아니다. 상세 절차·적용 조건·기대 결과의 기계 판독본은 [`assets/acceptance-tests.json`](../assets/acceptance-tests.json)을 기준으로 한다.

## 기본 원칙

프로토콜 적합성, 결정론적 정책 검사, 장애·복구, 실제 호스트·모델 기반 과제 평가는 서로 다른 증거로 관리한다. Conformance의 종료 코드 하나만으로 전체 적합성을 선언하지 않고, 적용 requirement set과 `pass/fail/skip/expected failure/not_scored`를 함께 기록한다.

모델 기반 평가는 모델 ID, 호스트 빌드, SDK·사양 버전, 정책·도구 설명 버전, fixture, 반복 횟수, 성공 기준, 비용·지연을 남긴다. 확률적 평가 결과는 결정론적 권한·승인 검사를 대신하지 않는다.

시험을 실행하지 않았으면 `not_run`으로 남긴다. 조건부 시험을 제외할 때는 `not_applicable`과 이유·검토 증거를 기록한다. 모든 프로젝트에 공통인 필수 검토 항목을 임의로 제외하지 않는다.

## 시험 범주

| 범주 | 시험 | 목적 |
|---|---|---|
| 설계·증거 | T01 | 책임자, 적용 판단, 증거 연결 확인 |
| 버전·전송 | T02–T07 | 지원 조합, 전송 경계, 호환 정책 확인 |
| 신원·인가 | T08–T12 | 검증된 신원과 객체·테넌트별 권한 확인 |
| 도구 계약 | T13–T15 | 입력·출력·오류·도구 의미의 일관성 확인 |
| 자격증명·데이터 경계 | T16–T21 | 위임, 민감 데이터, 비신뢰 입력과 실행 경계 확인 |
| 쓰기 안전성 | T22–T25 | 승인, 멱등성, 불명확 결과, 취소·복구 확인 |
| 상태·수명 | T26–T29 | 핸들, 상태, 캐시, 파일·보존 정책 확인 |
| 회복·감사 | T30–T32 | 성능 한도, 감사 추적, 추적 문맥 경계 확인 |
| 적합성·평가·릴리스 | T33–T36 | Conformance 범위, 실제 과제, 변경 게이트, 차단·회수 확인 |

## 공통 기록 필드

각 시험은 적용 여부, 시험자, 환경·버전, 실행 시각, fixture 또는 입력 버전, 결과, 증거 참조, 실패·미실행 사유를 남긴다. 실제 비밀이나 운영 데이터를 시험 fixture로 사용하지 않는다.

릴리스 판단에는 [`assets/release-gate-template.md`](../assets/release-gate-template.md)를 사용하고, 프로젝트별 결과는 [`assets/project-manifest.template.json`](../assets/project-manifest.template.json) 형식으로 기록한다.
