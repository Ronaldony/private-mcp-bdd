# 공통 통제 카탈로그

분류: 프로젝트 정책 제안. 모든 항목의 검토는 요구하되, 기능 구현 여부는 근거와 적용 조건으로 판단한다. 사양 요구의 강도는 지정 버전 원문에서 다시 확인한다.

## C01 · 목적·책임·영향 범위

질문: 누가 어떤 과제를 위해 어떤 데이터·행위에 접근하는가?

기준: 소유자, 비목표, 데이터 분류, 허용 작업, 실패 영향, 폐기 책임을 설계 기록으로 고정한다.

주 책임: 제품/도메인 책임자 / 적용: 모든 서버에서 검토

근거: R01, R23, R34 / 시험: T01

## C02 · 사양·SDK·호스트 호환성

질문: 어느 버전과 클라이언트 조합을 실제로 지원하는가?

기준: 사양 날짜, SDK 고정 버전 또는 커밋, 호스트 빌드, 전송 방식, 확장과 폴백 정책을 함께 고정한다.

주 책임: MCP 어댑터/클라이언트 담당 / 적용: 모든 서버에서 검토

근거: R02, R03, R29 / 시험: T02, T03, T04, T33

## C03 · 배포·전송·프로세스 경계

질문: 어떤 프로세스와 네트워크 경계에서 실행되는가?

기준: stdio의 실행 권한·표준출력과 HTTP의 TLS·Origin·프록시·요청 크기 제한을 해당 프로파일별로 통제한다.

주 책임: 플랫폼/서버 운영 / 적용: 전송 방식별 구현

근거: R04, R05, R10 / 시험: T05, T06, T07

## C04 · 검증된 신원

질문: 사용자·서비스·테넌트 신원은 누가 증명하는가?

기준: 신원을 검증된 인증 문맥 또는 명시한 로컬 OS/프로세스 신뢰 경계에서 도출한다. 모델 인수와 clientInfo를 인증 근거로 쓰지 않는다.

주 책임: 인증 어댑터/IdP 연동 / 적용: 모든 서버에서 경계 정의; 원격 인증은 프로파일별

근거: R07, R08, R15 / 시험: T08, T09

## C05 · 매 호출·객체별 인가

질문: 이 주체가 지금 이 객체에 이 행위를 할 수 있는가?

기준: 서버 또는 신뢰 가능한 도메인 계층에서 기본 거부와 객체·테넌트·행위별 검사를 수행한다. 목록 필터와 실제 호출 인가를 분리한다.

주 책임: 서버 정책/도메인 계층 / 적용: 보호 자원·행위가 있으면 실행 경계에서 강제

근거: R06, R31 / 시험: T10, T11, T12

## C06 · 도구 계약·모델 사용성

질문: 도구의 의미·입출력·부작용·오류가 오해 없이 정의되는가?

기준: 작업 중심 인터페이스, 엄격한 스키마, 제한된 결과, 안정적 이름, 의미가 다른 오류와 성공·부분성공·불명확 결과를 명시한다.

주 책임: 도구 설계/도메인 담당 / 적용: 노출하는 primitives와 도구별

근거: R06, R23 / 시험: T13, T14, T15, T34

## C07 · 비밀·하위 시스템 위임

질문: 어떤 자격증명으로 누구를 대신해 하위 시스템을 호출하는가?

기준: MCP 수신 토큰과 하위 서비스 토큰의 대상을 구분하고 최소 권한·수명·회수·안전한 저장을 정의한다. 환경 전체를 자식 프로세스에 넘기지 않는다.

주 책임: 인증/커넥터/비밀 관리 / 적용: 자격증명 또는 외부 API가 있을 때 구현

근거: R08, R09, R10 / 시험: T16, T17

## C08 · 비신뢰 콘텐츠·입력·정보 유출 경로

질문: 공격자가 바꿀 수 있는 텍스트·URL·경로·명령이 어디로 흐르는가?

기준: 데이터와 지시를 구분하고 URL·파일·DB·셸 실행 경계와 외부 반출 정책을 코드로 제한한다. 출처 표시나 프롬프트만을 차단 수단으로 간주하지 않는다.

주 책임: 호스트+서버+실행 샌드박스 / 적용: 모든 입력 검토; 위험한 실행·외부 콘텐츠는 강화

근거: R24, R25, R27, R32, R33 / 시험: T18, T19, T20, T21

## C09 · 쓰기·승인·재시도 안전성

질문: 변경이 중복·변조·무승인으로 일어날 수 있는가?

기준: 위험도에 맞춘 승인, 인수·대상 버전 결속, 원자적 멱등성, 충돌 감지와 불명확 결과의 확인 절차를 구현한다.

주 책임: 도메인 실행기/승인 서비스 / 적용: 상태 변경·공개 전송·비용 유발 등 위험 행위

근거: R01, R13, R20, R31 / 시험: T22, T23, T24, T25

## C10 · 업무 상태·핸들·재개

질문: 호출 사이의 상태를 누가 소유하며 얼마나 보존하는가?

기준: 명시적 업무 핸들에 소유자·테넌트·수명·상태 전이를 연결한다. MRTR 상태는 의미가 있으면 무결성·결속을 검증하고 필요 시 일회성을 저장소에서 강제한다.

주 책임: 서버 상태/워크플로 계층 / 적용: 업무 상태·장기 작업·MRTR이 있을 때

근거: R06, R11, R14 / 시험: T26, T27

## C11 · 데이터 수명·캐시·산출물

질문: 원본·응답·캐시·파일·로그·백업은 어디에 얼마 동안 남는가?

기준: 데이터 흐름과 수명·삭제 범위·출력 최소화·캐시 인증 문맥·산출물 접근을 정한다. private 캐시는 암호화나 인가의 대체물이 아니다.

주 책임: 데이터/플랫폼/호스트 담당 / 적용: 데이터 처리·저장·캐시별 검토

근거: R01, R06, R12 / 시험: T28, T29

## C12 · 실패·성능·취소·회복

질문: 느림·부분 실패·끊김·재시작에도 결과를 정확히 설명하는가?

기준: 도구별 시간·비용·출력·동시성 예산, 재시도 분류, 취소 전파, 불명확 상태 확인과 복구 경로를 정의한다.

주 책임: 서버/도메인/SRE / 적용: 모든 서버에서 규모에 맞게

근거: R04, R06, R13 / 시험: T24, T25, T30

## C13 · 관측·감사·사고 대응

질문: 누가 무엇을 허용받아 실제 어떤 효과를 냈는지 복원 가능한가?

기준: 요청·업무 작업 식별자를 분리하고 정책 결정·도구 버전·결과를 최소 감사 로그에 남긴다. 비밀과 본문 노출을 제한하고 긴급 차단·회수를 시험한다.

주 책임: 운영/보안/도메인 담당 / 적용: 규모·위험도에 맞춘 기록과 대응

근거: R06, R17, R31 / 시험: T31, T32, T36

## C14 · 검증·평가·증거

질문: 정합성·안전성·실제 과제 성공을 무엇으로 입증하는가?

기준: 프로토콜·정책·장애·적대적 조합·실제 호스트·과제 평가를 분리한다. 버전·fixture·실행 기록과 누락 시험을 함께 검토한다.

주 책임: 개발/QA/보안 검토자 / 적용: 모든 서버에서 위험도에 맞게

근거: R23, R25, R26, R27, R29 / 시험: T01, T33, T34, T35

## C15 · 공급망·변경·릴리스

질문: 어떤 검토된 코드·설정·도구 설명이 배포되는가?

기준: 의존성·이미지·설정·도구 설명을 버전 관리하고 출처와 변경을 검토한다. canary·롤백·철회와 지원 종료를 정책으로 정한다.

주 책임: 빌드/릴리스/운영 책임자 / 적용: 모든 배포에서 규모에 맞게

근거: R18, R25, R28, R35 / 시험: T35, T36

## C16 · 정책 소유권·예외·재검토

질문: 누가 예외를 승인하며 언제 재검토하는가?

기준: 통제마다 책임자·증거·적용 조건·예외 사유·보완책·만료·재검토 계기를 남긴다. 사양 MUST 위반을 내부 승인만으로 준수로 표시하지 않는다.

주 책임: 프로젝트 책임자/독립 검토자 / 적용: 모든 서버에서 검토

근거: R01, R29, R30 / 시험: T01, T35
