# 프로토콜과 조건별 프로파일

근거 확인일: 2026-09-10. 특정 날짜의 사양 규범과 아래 프로젝트 정책 제안을 구분한다. 변경된 최신 페이지를 과거 환경의 호환 근거로 쓰지 않는다. 출처 ID는 research-evidence.md와 연결된다.

## 버전 결정

공식 latest는 열람 당시 2026-07-28로 연결되었다. Modern은 요청별 메타데이터 기반, Legacy는 2025-11-25 및 이전의 initialize 기반, Dual-era는 양쪽 지원이다. Modern의 server/discover 구현과 버전 오류 처리는 해당 사양을 따른다. 구체적인 지원은 SDK·호스트·전송 조합으로 시험한다. [R01–R03]

Modern에 구버전 Mcp-Session-Id, initialize, GET 구독·재개 흐름을 기본 전제로 이식하지 않는다. Dual-era가 필요할 때만 버전별 어댑터를 유지한다. 최신 사양 문서에 남은 요약 문구와 상세 규정이 다르면 해당 날짜의 세부 사양·스키마를 대조하고 차이를 기록한다. [R02–R04]

## 전송

stdio: 승인된 실행 파일·인수·작업 폴더, 환경변수 허용 목록, 최소 파일 접근, 프로토콜 stdout/일반 로그 stderr, 종료·재시작을 정의한다. [R05, R10]

Streamable HTTP: POST의 JSON/SSE 응답, 필수 헤더와 메타데이터 일치, Origin이 있을 때 유효성, 프록시·요청 크기·중단·한도를 시험한다. 현대식 HTTP에서도 SSE 응답을 사용하므로 SSE 전부가 폐기되었다고 설명하지 않는다. [R04]

## 인증·인가

MCP의 인증 기능 자체는 전체적으로 선택 사항이다. HTTP 인증을 구현하면 해당 사양 프로파일을 따른다. stdio에 같은 HTTP OAuth 흐름을 일괄 적용하지 않는다. 단, 본 프로젝트 기준으로 보호되는 원격 데이터·작업은 검증된 사용자 또는 서비스 신원을 요구한다. [R07]

사용자 위임, 서비스 계정, 클라이언트 앱, 테넌트를 구분한다. 모델 인수는 인증 증거가 아니다. 수신 토큰의 대상과 하위 서비스 자격증명을 분리하고, 등록은 환경에 따라 사전 등록/CIMD/호환 경로를 선택한다. DCR의 폐기 예정 상태와 OAuth 2.1 문서의 표준화 상태를 정확히 표현한다. [R08–R10, R15, R16]

## 상태·캐시·확장

업무 상태는 서버 발급 핸들, 소유권, 수명, 재인가, 상태 전이로 관리한다. MRTR을 쓰면 의미 있는 requestState의 무결성과 필요한 결속을 검증한다. 서명만으로 재사용이 방지되지는 않는다. [R06, R11]

캐시 가능 응답은 버전별 ttlMs/cacheScope 계약을 따른다. private 결과는 인증 문맥을 넘겨 공유하지 않는다. 캐시 표시를 암호화·권한 검증으로 해석하지 않는다. [R12]

Tasks·기계 인증·기업 인증은 선택 확장이다. Roots·Sampling·Logging은 확인한 최신 변경 기록에서 폐기 예정이지 즉시 제거와 같지 않다. 새 기본 의존성으로 추가하지 말고 호환 요구와 대체를 명시한다. [R03, R14–R16]

## 조합할 구현 프로파일

P1 local_stdio: 단일 사용자 로컬 프로세스 경계.

P2 remote_http: 인증된 원격 HTTP와 네트워크·프록시 경계.

P3 multitenant: 객체·테넌트·캐시·작업·로그 격리 추가.

P4 unattended: 사용자 위임과 구별되는 무인 서비스 신원과 사전 승인 범위.

P5 risky_writes: 승인, 원자적 멱등성, 충돌·불명확 결과·복구.

P6 execution: 파일·브라우저·코드·쿼리 실행의 격리·목적지·시간·반출 한도.

P7 stateful: 업무 핸들, MRTR 또는 장기 작업의 수명·재개·취소.

P1/P2 중 실제 전송을 기준으로 선택하고, 나머지는 위험·기능에 맞게 추가한다. 이 프로파일 이름은 프로젝트 설계 분류이지 공식 MCP capability 명칭이 아니다.
